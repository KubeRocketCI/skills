# Ownership verdict

Operators on the platform do not call each other. Each one reconciles its own resources and hands over through the cluster. Something that looks stuck is a handoff that did not happen. Find the handoff, then say who owns it.

## Handoff map

| Step | Handoff | Usual owner when it breaks |
|---|---|---|
| 1 | Project created, repository and webhook provisioned on the Git provider | platform team (Git server credentials, token scopes), external system (provider outage, project missing) |
| 2 | Git event reaches the platform and becomes a PipelineRun | platform team (webhook, event listener, interceptor), application team (branch not registered on the platform) |
| 3 | PipelineRun executes: checkout, build, test, scan, image build, push | application team (code, tests, Dockerfile, lint, quality gate), platform team (registry or SonarQube credentials, cache, cluster capacity) |
| 4 | Successful build adds a tag to the CodebaseImageStream and tags the repository, see the versioning table in [vocabulary.md](vocabulary.md) | platform team when the final tasks fail after a good build |
| 5 | Deploy run points the Argo CD Application, generated by the deployment flow's ApplicationSet, at the chosen version | application team (custom deploy pipeline), platform team (Argo CD integration, cluster registration) |
| 6 | Argo CD renders the chart and syncs it to the environment namespace | application team (chart in `deploy-templates/`, values in the GitOps repository), platform team (repository credentials, target cluster reachability, admission webhooks) |
| 7 | Workload becomes healthy | application team (image, configuration, probes, resources), platform team (pull secret, quotas, node capacity) |
| 8 | Quality gates pass and the version is promoted to the next environment | application team (autotests, approvals), platform team (approval controller) |

## Reading Argo CD Application state

| State | Meaning | Usual owner |
|---|---|---|
| Health `Missing`, Sync `OutOfSync`, no operation | Nothing was deployed yet, or the environment was cleaned. Not a failure. | nobody |
| `ComparisonError` mentioning cluster info, a timeout, or an unreachable server | Argo CD cannot reach the target cluster. | platform team |
| `ComparisonError` mentioning manifest generation or `helm template` | The chart or its values do not render. | application team |
| `ComparisonError` saying the target revision cannot be resolved | The version has no matching Git tag: the build did not finish, or the version string is wrong. For `semver` the revision is `build/<version>`, otherwise the image tag. A project on the deprecated `edp` versioning is tagged `build/<version>` but deployed from the plain image tag. | application team first, platform team if builds succeed without tagging or the project uses `edp` versioning |
| Health `Progressing` for long, or `Degraded` | Pods do not become ready. Continue at step 7 with pod events and logs. | application team, unless the events point at pull secrets, quotas, or nodes |
| Healthy and `OutOfSync` | Live state drifted from Git, often a manual change. | whoever changed it |
| Operation `Failed` mentioning an admission webhook or an internal error | The cluster rejected the apply. | platform team |

## Verdict format

```text
Owner: application team | platform team | external system
Cause: <one sentence naming the failed handoff>
Evidence: <commands run and the decisive output lines>
Next step: <the fix, or an escalation bundle when the owner is not the user>
```

Start the answer with this block, the `Owner` line first, also when the user suggested a cause: the block answers it under `Cause`. When the evidence does not separate two owners, say so, name the single check that would, and who can run it.

## Escalation bundle

When the owner is not the user, give them something they can forward as is, in the same answer. A fact you have not read yet is a placeholder with the command that reads it, for example `<cluster: infrastructure.cluster of krci env get billing dev>`:

- project, deployment, and environment names, plus the target cluster by its registered name: `infrastructure.cluster` of `krci env get`, or `Stage.spec.clusterName`. An API server address alone does not identify it,
- the exact error or condition text, unedited,
- when it started and the last version that worked,
- the commands already run, so nobody repeats them,
- what was ruled out.

Leave out secrets, tokens, and anything copied from a secret.
